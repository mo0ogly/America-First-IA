Dear CERT-Team,

Secure Shell (SSH) is a common protocol for operating network services over untrusted networks. It is 
often used for remote administration of Linux/Unix systems.

In addition to logging in using a username and password, SSH also allows for authentication using 
cryptographic keys (SSH keys).
The keys authorized for authentication are usually stored in the ".ssh/authorized_keys" directory of the 
respective user.

Every day, cybercriminals carry out brute force attacks to compromise SSH servers accessible from the 
Internet having weak passwords on user accounts with common names. If a user account with 
administrative privileges (e.g. "root") is compromised, the malicious actors can gain complete control of 
the system. The compromised servers are then often abused for criminal activities.

After compromising a user account, the malicious actors often install a SSH key for keeping access to the 
system even if the legitimate user changes the password.

The SSH protocol allows for checking remotely if a particular known SSH key is authorized for 
authentication with a specific user account on a SSH server. Using this feature, a group of researchers 
checks SSH servers accessible from the Internet for implants of known malicious SSH keys and classifies 
the servers as compromised for positive results.

The researchers provided CERT-Bund with information on SSH servers they found to be compromised for 
victim notification.

Please find below a list of IP addresses of SSH servers on your networks found to be compromised. All 
timestamps are UTC.
"username" is the name of the compromised user account.
"key_hash" is the SHA256 hash of the installed malicious SSH key.

We would like to ask you to notify the owners of the affected hosts and/or the responsible network 
providers of the compromises.

IMPORTANT:
The reported systems have already been compromised!
It is NOT sufficient to just change the password of the user account and remove the malicious SSH key.
Instead, a forensic analysis should be carried out to determine what changes have been made to the 
system by the malicious actors and what impact this had on your network.
Finally, the compromised system should be reinstalled.
